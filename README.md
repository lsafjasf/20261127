# scalediag

用于区分“显示器缩放后文字软边”来源的 Go 诊断工具。它成对读取**源帧序列**和**缩放后的显示采集帧序列**，比较局部梯度、块边界周期和帧间稳定性，输出 `source`、`encoding`、`display_sampling` 或混合归因。

实现只使用 Go 标准库，不依赖外部图像处理工具。

## 快速开始

```bash
go build -o scalediag ./cmd/scalediag

./scalediag \
  --source ./native-frames \
  --scaled ./scaled-capture \
  --roi 180,120,900,260
```

`--roi` 使用**源帧像素坐标**，格式为 `x,y,w,h`。诊断文字软边时应尽量只框住文字区域，避免大面积纯色背景或无关图形稀释指标。

输出 JSON：

```bash
./scalediag --source ./native --scaled ./capture --roi 180,120,900,260 --json
```

也可以直接传逗号分隔的文件：

```bash
./scalediag \
  --source native-1.png,native-2.png,native-3.png \
  --scaled capture-1.png,capture-2.png,capture-3.png
```

目录会按自然顺序展开，因此 `frame_2.png` 排在 `frame_10.png` 前面。源序列和缩放序列必须帧数相同、按相同顺序配对，并覆盖相同视口。

## 采集要求

- 源帧应是缩放发生之前的原始渲染帧，尽量使用无损 PNG；不要拿另一张经过显示缩放的截图当源帧。
- 缩放帧应是目标显示器缩放后、在设备像素分辨率下抓取的画面。两者宽高比必须一致，实际倍率由尺寸自动推断。
- 至少提供 2 帧；建议 3–10 帧静态画面。多帧用于区分固定空间伪影与编码/码率波动。
- 采集期间关闭光标、动画、滚动和视频播放，避免真实内容变化被误当成编码闪烁。
- 若更换窗口大小、显示器缩放比例或抓取位置，源帧和缩放帧必须同步重新采集。

## 三类证据

### 1. 局部梯度与边缘宽度

对每个序列计算中心差分梯度、梯度分位数、拉普拉斯高频能量，以及强边缘法向上的 10–90% 过渡宽度。缩放帧的梯度与拉普拉斯能量会按推断倍率换算回源像素尺度，避免“像素变多所以梯度看起来不同”的偏差。

关键比较值：

- `edge_width_ratio`：缩放后边缘宽度 / 源边缘宽度。
- `sharpness_retention`：按倍率校正后的高频能量保留率。
- `gradient_retention`：按倍率校正后的梯度 RMS 保留率。

边缘宽度基于强边缘样本的中位数，对文字笔画、字号和抗锯齿差异比单一方差更稳健。

### 2. 块边界

在序列平均帧上，对相邻列/行的亮度差做统计。只使用局部对比度较低的像素，避免文字自身边缘制造虚假周期。对候选块尺寸 `8,16,32` 搜索最佳相位，并计算：

- 边界线平均差 / 内部线平均差。
- 边界超额比例和显著性 z 分数。
- 与源帧同尺寸、同方向结果的差值。

若缩放帧出现源帧没有的稳定块网格，优先判为编码/传输链路问题。块尺寸可通过 `--block-sizes` 调整，例如 `--block-sizes 4,8,16`。

### 3. 多帧稳定性

对每个像素累积时域均值与方差，并计算：

- `delta_norm`：相邻帧平均绝对差，除以序列亮度标准差。
- `edge_noise_norm`：强梯度区域时域标准差，除以亮度标准差。

源帧稳定而缩放帧出现额外帧间变化，是压缩噪声、码率波动或传输重编码的强证据。正常的显示采样软化通常稳定，不会逐帧随机变化。

## 归因规则

工具按以下优先级给出主结论：

1. **`encoding`**：缩放序列新增稳定块网格，或源帧稳定时缩放序列出现额外帧间闪烁。
2. **`source_and_display`**：源帧已有软边或块网格，缩放后又出现额外软化，但没有新增编码证据。
3. **`source`**：源帧边缘已宽，或源帧已有块网格，而缩放后没有新增同类伪影。
4. **`display_sampling`**：源帧锐利，缩放后边缘按物理尺度显著变宽，且没有新增块网格或闪烁。
5. **`inconclusive`**：证据不足，通常需要更紧的 ROI、更多静态帧或更无损的采集。

这里的 `display_sampling` 包含显示器缩放、合成器缩放、GPU 重采样和重建滤波造成的软化；工具不会进一步区分这些显示链路内部阶段。

## 输出

文本模式会打印结论、置信度、逐项证据、两个序列的尺寸/帧数/边缘宽度/块边界/时域指标。

JSON 的主要字段：

```json
{
  "verdict": "display_sampling",
  "confidence": 0.83,
  "summary": "...",
  "source": {
    "spatial": {"gradient": {}, "hf_norm": 1.27, "edge_width_median_px": 0.81},
    "block": {"best": {}, "candidates": []},
    "temporal": {"delta_norm": 0.0, "edge_noise_norm": 0.0}
  },
  "scaled": {},
  "comparison": {
    "scale_x": 1.5,
    "scale_y": 1.5,
    "sharpness_retention": 0.41,
    "gradient_retention": 0.70,
    "edge_width_ratio": 4.89,
    "block_excess_delta": 0.03,
    "temporal_delta_diff": 0.0,
    "edge_noise_delta": 0.0
  },
  "evidence": []
}
```

指标是诊断证据，不是绝对画质评分。阈值以 8 位 sRGB 文字画面为基准；极低对比度文字、HDR、亚像素抗锯齿或强噪声画面应结合证据项人工复核。

## 限制

- 工具假定源帧与缩放帧覆盖同一视口；不支持自动配准、裁切差异或滚动偏移。
- 动画 GIF 只读取第一帧。视频请先抽成无损帧序列。
- 源帧若本身已经过压缩，`source` 归因表示伪影在进入本次显示器缩放前已经存在，不代表原始内容一定模糊。
- 非整数倍双线性/双三次缩放天然会改变边缘过渡宽度；只要没有编码证据，这类稳定软化会归入 `display_sampling`。
- 块边界统计依赖画面中存在低对比度区域。若 ROI 内全是文字笔画，块证据可能不足。
