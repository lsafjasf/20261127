# 显示器色域几何比较（Go 标准库）

输入厂商给出的红、绿、蓝、白 CIE 1931 xy 坐标，计算：

- RGB 三角形的 xy 与 CIE 1976 u′v′ 面积；
- 显示器色域与目标色域的交集多边形、交集面积和覆盖率；
- 以白点（或统一目标白点）为中心的不可覆盖角度区间、径向缺口；
- 白点是否能由 RGB 基色非负混出，以及 RGB 相对亮度贡献；
- 两台显示器的面积/覆盖率排序差异。

工作区最初没有真实显示器坐标，因此这里提供可运行程序、JSON 模板、标准色域预设和验证样本；把厂商坐标填入 `examples/sample_input.json` 即可得到采购结论。

## 运行

```bash
go test -count=1 -v ./...

# 内置 P3-like / AdobeRGB-like 示例
go run ./cmd/gamut -demo

# 使用真实输入
go run ./cmd/gamut -input displays.json -format text
go run ./cmd/gamut -input displays.json -format json > report.json

# 方向中心可选 display_white（默认）、target_white、xy_origin
go run ./cmd/gamut -input displays.json -center target_white
```

零第三方依赖，仅使用 Go 标准库。

## 输入格式

坐标支持 `[x, y]` 或 `{"x": x, "y": y}`。目标可写预设名 `"srgb"`、`"display-p3"`、`"adobergb"`、`"bt2020"`，也可给 RGB 或任意多边形点。

```json
{
  "direction_center": "display_white",
  "target": "srgb",
  "displays": [
    {
      "name": "Monitor A",
      "red":   [0.680, 0.320],
      "green": [0.265, 0.690],
      "blue":  [0.150, 0.060],
      "white": [0.3127, 0.3290]
    },
    {
      "name": "Monitor B",
      "red":   [0.6400, 0.3300],
      "green": [0.2100, 0.7100],
      "blue":  [0.1500, 0.0600],
      "white": [0.3127, 0.3290]
    }
  ]
}
```

完整对象式目标可写为：

```json
"target": {
  "name": "my-target",
  "red": [0.64, 0.33],
  "green": [0.30, 0.60],
  "blue": [0.15, 0.06],
  "white": [0.3127, 0.3290]
}
```

## 计算口径

- RGB 三点按有向面积归一化为逆时针三角形；面积为鞋带公式绝对值的一半。
- u′v′ 换算为 `u' = 4x / (-2x + 12y + 3)`、`v' = 9y / (-2x + 12y + 3)`。
- 交集使用 Sutherland–Hodgman 凸多边形裁剪，显示器 RGB 三角形为裁剪多边形；JSON 会返回交集顶点和面积。
- 目标覆盖率是 `交集面积 / 目标面积`。`xy` 与 `u'v'` 分别计算，避免把一种平面面积口径当成唯一答案。
- 不可覆盖方向通过拆分目标边与显示器三角形边界得到外部弧段，再围绕白点合并成角度区间。角度约定为 xy 平面内 `0° = +x`，逆时针增加。
- 白点不是第四个体色域顶点；只改变白点时，RGB 三角形面积和交集不变。白点用于方向中心，并通过求解 `M * S = XYZ(W)` 检查 RGB 是否能非负混出该白点。

## 已包含的验证

`go test -count=1 -v ./...` 覆盖：

- 已知三角形面积、顺时针/逆时针输入、完全重合和包含关系；
- 已知交集：单位目标三角形与等底等高偏移三角形的交集为 `1/3`，目标覆盖率为 `2/3`；
- 不同白点 D65/D50 使用相同 RGB 时，面积与交集完全不变，但白点混合系数和方向中心改变；
- 近等面积样本中，面积略大的细长/偏移三角形只有约 `66.9%` 目标覆盖，而对齐样本为 `100%`，比较结果会标记面积排序与覆盖排序相反；
- 同心缩小三角形产生完整 `360°` 缺失方向；切去一个角只产生一个已知窄扇区；
- 示例 JSON 可解析、报告可序列化，文本报告包含画质限制声明。

可直接运行物理 xy 范围内的等底等高样本：

```bash
go run ./cmd/gamut -input examples/equal_height_sample.json
```

该样本中两台显示器的 xy 面积都为 `0.112050`，但偏移绿基色的一台只覆盖 sRGB 的 `66.67%`，并给出约 `0.18°–124.57°` 的缺失方向扇区。这说明相同面积不代表相同目标适配。

## 解释边界

不要把色域面积大小直接解释为画质好坏。厂商只给 RGBW 色坐标时，能严格计算的是二维色度范围及其与指定目标色域的几何关系；无法据此判断：

- 三维色彩体积、峰值亮度和暗部表现；
- Gamma/传递函数、色深、色阶断裂和 tone mapping；
- 实际校色、色准、均匀性、持久度和面板素质；
- 不同观看白点下的 chromatic adaptation 与主观偏好。

若两台显示器白点不同，原始 CIE xy 几何交集仍是绝对色度刺激的比较；角度方向可分别看本机白点，也应同时用统一目标白点复核。需要主观 hue 对齐时，应另做明确的 chromatic adaptation，而不是悄悄改动面积公式。
